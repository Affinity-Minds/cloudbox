# ADR 0002 — Two identity systems, nothing shared: customers (email code) and staff (password + authenticator)

**Status:** Accepted, amended 2026-09-27 (owner decisions: closed sign-in; staff use password + authenticator, ADR 0009; staff and customer identity are two separate systems with nothing shared; a discreet staff surface)
**Context:** Slices 1.1/1.2 (WT-1), WT-8 reviews H-1/H-2/M-3/S-1…S-8/T-1/T-2/U-1
**Stakeholders:** WT-0, WT-1 (Auth), WT-2 (memberships), WT-12 (email providers)

## Decision

### Two identity systems, nothing shared
| | Customers (tenant members) | Staff (Super Admin, Admin, Support, Read Only) |
|---|---|---|
| Sign-in | email → six-digit emailed code | email + password → authenticator app (TOTP) or a backup code |
| UI | `/login`, `/portal` | `${OPS_BASE_PATH}/login`, console under `${OPS_BASE_PATH}` (default `/ops`) |
| Better Auth instance | `createCustomerAuth(env)`, plugins: `emailOTP` only | `createStaffAuth`/`createAuth(env)`, `emailAndPassword` + `twoFactor` only |
| Mount | `/api/auth/*` | `/api/ops/auth/*` |
| Tables | `customer_users`, `customer_sessions`, `customer_accounts`, `customer_verifications`, `customer_rate_limit` | `staff_users`, `staff_sessions`, `staff_accounts`, `staff_verifications`, `staff_two_factor`, `staff_rate_limit` |
| Session cookie | `cbx_session` (`__Secure-` on https) | `cbx_ops_session` |
| Secret | `CUSTOMER_AUTH_SECRET` | `STAFF_AUTH_SECRET` |
| Linked by | `tenant_memberships.user_id → customer_users.id` | `staff_members.user_id → staff_users.id` |

- The plugin lists are disjoint, so the endpoint sets are disjoint by construction; each mount also has
  an exact allowlist (everything else is the ordinary 404).
- `requireStaff()` / `requirePermission()` read only the staff cookie and staff tables. `requireUser()`
  / `requireTenantStanding()` read only the customer cookie and customer tables. A customer session on
  a staff route is 401, and a staff session on a customer route is 401. Routes both audiences use
  (session, logout, and WT-2/WT-3 routes open to staff *or* tenant members) evaluate each principal from
  its own system; nothing is mixed. A person who is both staff and a customer has two identities.
- The two table sets are generated by `auth@1.7.6 generate` from `src/auth/cli.ts` (staff) and
  `src/auth/cli-customer.ts` (customers), in `src/db/schema.ts`, migrations 0003/0004 (rewritten in place
  before any deploy; production has only 0001/0002).

### Customers: closed sign-in with emailed codes
1. **Better Auth `emailOTP`.** Codes are 6 digits, valid 5 minutes and single use, with 5 attempts each. They are stored encrypted, and a resend re-sends the still-valid code. Only `type: "sign-in"` codes are issued.
2. **Closed sign-in.** Sign-in never creates an identity. An address with no `customer_users` row gets the same answer (`200 {success:true}`), but nothing is generated, stored or sent; this is audited as `AUTH_OTP_SENT {outcome: "unknown_email"}`. A code for such an address fails like a wrong code. Customer identities are created only by admin actions: tenant memberships (`ensureCustomerByEmail`).
3. **One spelling per mailbox (U-1).** Addresses are NFKC-normalised and lower-cased *before* validation (`normalizeEmail` in contracts). The gate refuses an address that does not parse (400) and passes the normalised value on.
4. **Limits.** A client is an IPv4 address or an IPv6 /48.
   - Better Auth's per-IP limits: 3 sends / 60 s and 3 code sign-ins / 60 s.
   - Per (email, client): 5 sends / 15 min and 10 failed code checks / h.
   - Only clients that requested a code can spend its attempts.
   - Per address, across all clients, 30 failed checks / h is a **budget, not a lock**. Above it, a Turnstile token is required. Without `TURNSTILE_SECRET_KEY` the fallback is a 15-minute cooldown, `AUTH_ACCOUNT_COOLDOWN`. This cooldown is the only per-account denial in the system, and it exists only until Turnstile is configured.
5. **Email** goes through WT-12's provider registry (`sendEmail`), with the Cloudflare Email Service binding `EMAIL` as fallback. The send result is audited, and a failure never changes the HTTP response.

### Staff: password + authenticator (ADR 0009)
Staff sign-in, the forced first-sign-in setup and the admin-set initial passwords are described in ADR 0009 and the WT-1 handoff. The pieces:
- **Forced setup:** at first sign-in the initial password must be changed, then an authenticator enrolled.
- **Initial password:** set by an administrator; `POST /api/v1/staff` resets it.
- **Replay-safe codes:** an accepted TOTP code cannot be reused.
- **No trusted devices.**
- **Lockout per client:** 5 failed passwords per (email, client) in 15 min, with no per-account lock.
- **Bootstrap:** the bootstrap super admin is seeded into `staff_users` only.

### Discreet staff surface
- The staff console and its login live under `OPS_BASE_PATH` (a Worker var; default `/ops`; the owner may set a long random slug). Customer surfaces never link to it.
- The Worker marks the SPA document as the ops shell only at known console routes under the base: a meta tag the SPA reads to mount the staff router, `<meta name="robots" content="noindex">` and `X-Robots-Tag: noindex`.
- Unknown paths under the base get the ordinary SPA document. There is no robots.txt entry.
- `/api/ops/*` responses carry `X-Robots-Tag: noindex`.

## Alternatives rejected
- **Open sign-up:** any probe created a `user` row.
- **One Better Auth instance with allowlists:** the owner requires nothing shared.
- **A single login page with two tabs:** it advertises the staff console.
- **429 on per-account ceilings:** anyone could lock anyone out (H-1, S-1, S-2).
- **Resend, SMTP relay or custom OTP:** see git history (WT-12 later added a provider registry).

## Consequences
- **Two identities for one person:** someone who is both staff and a tenant member has two separate identities, one in each system.
- **Old secret:** `BETTER_AUTH_SECRET` is retired. The deploy syncs `STAFF_AUTH_SECRET` and `CUSTOMER_AUTH_SECRET` once each.
- **Moving the console:** changing `OPS_BASE_PATH` changes the console URL. Bookmarks break by design, and the SPA needs no rebuild.
