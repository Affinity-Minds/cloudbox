# Slice 2.2 — Device cryptographic identity

## Goal

Every CloudBox device generates a unique, non-exportable asymmetric key pair. If TPM is present, the key is sealed in the TPM; otherwise, a software fallback explicitly marks lower assurance. The public key is registered during enrollment.

## Existing capabilities reused

- Windows CNG (Cryptography API: Next Generation) with TPM or Software KSP
- `System.Security.Cryptography.CngKey` (.NET BCL)
- Microsoft Platform Crypto Provider (TPM 2.0 driver stack)
- RSA 2048-bit key generation (NIST-approved, standard)
- JWK export format for API payloads

## Data changes

**Schema (from foundation migration 0003, applied by WT-3 during enrollment):**
- `devices(id 'dev_…' PK, tenant_id, name, status, device_public_key_jwk, device_key_thumbprint UNIQUE, key_protection CHECK('tpm','software'), hostname, windows_build, agent_version, last_seen_at, last_health_json, enrolled_at, revoked_at)`

## Authorization

- Device public key is intended for server use only
- Private key never leaves the device or is exported
- Key thumbprint (SHA-256 of JWK) used as unique device identifier

## Audit events

- `DEVICE_KEY_GENERATED` — device_id (once enrolled), key_protection ('tpm'|'software'), timestamp
- Logged only during enrollment, not on every startup

## Tests

**Happy path (physical Windows test machine):**
- Agent starts, detects TPM (if available)
- Generates RSA-2048 key in TPM KSP
- Exports public JWK (modulus, exponent, kid=thumbprint)
- Verifies key is non-exportable (attempt to export private key fails)
- Persists kid/thumbprint locally for enrollment

**Fallback (software key when TPM unavailable):**
- Detects TPM missing (or explicitly disabled)
- Generates key in Software KSP
- Marks `key_protection='software'` in enrollment payload
- Exports public JWK
- Verifies software key is more permissive (test extraction; verify local protection sufficient)

**Negative tests:**
- Verify private key cannot be exported
- Verify key persists across service restart
- Verify key thumbprint deterministic (same key = same thumbprint)

## Demo path

```
Windows command prompt (as Administrator):

1. Run agent setup
2. Agent starts; detects TPM
3. Check agent logs:
   "Device key protection: tpm"
   "Device key thumbprint: <SHA256-hex>"
4. (During enrollment, public key is in JWK format)
5. Restart service: net stop CloudBoxAgent && net start CloudBoxAgent
6. Verify logs show same key thumbprint
7. If testing software fallback:
   a. Disable TPM in BIOS or mock test
   b. Delete local key storage
   c. Agent restart generates new software key
   d. Logs: "Device key protection: software" with warning
```
