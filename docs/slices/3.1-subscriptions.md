# Slice 3.1 — Subscription and entitlement data model

## Goal

Tenants can hold subscriptions for defined plans (e.g., "Pro", "Enterprise"). Each subscription specifies the number of licensed users, offline grace period, and feature flags. Entitlements are issued per device and are machine-bound.

## Existing capabilities reused

- `plans`, `subscriptions`, `entitlements`, `signing_keys` tables from foundation migration 0003
- Drizzle ORM for plan/subscription queries
- Audit service for subscription changes
- Entitlement generation counter for versioning (Slice 3.2)

## Data changes

**Schema (from foundation migration 0003):**
- `plans(code PK, name, max_devices, max_managed_users, features_json, offline_grace_days, renewal_warning_days)`
  - Seeded with sample plans (to verify in foundation.md)
- `subscriptions(id 'sub_…', tenant_id, plan_code, status CHECK('trial','active','past_due','suspended','cancelled'), valid_from, valid_until, max_managed_users, features_json, offline_grace_days, renewal_warning_days, created_at, updated_at)`
- `entitlements(id 'lic_…', subscription_id, device_id, generation INT, claims_json, token TEXT, issued_by, issued_at, valid_until, revoked_at, UNIQUE(device_id,generation))`
  - `token` field is compact JWE (never logged, never exposed except to authorized device)
- `signing_keys(kid PK, alg, public_jwk, status CHECK('active','retired'), created_at)`
  - Private key in Wrangler secret `ENTITLEMENT_SIGNING_JWK`

## Authorization (as built)

- Staff permissions (rows in `role_permissions`, WT-1 middleware): `subscription.view` (plans, lists, screens, entitlement history), `subscription.manage` (create/patch subscriptions), `license.issue`, `license.renew`, `license.revoke`.
- Seed matrix: super_admin all; admin all except `license.revoke`; support and read_only `subscription.view` only.
- Tenant-portal access (tenant owners) is not part of this slice.

## API (as built, `/api/v1`)

| Method | Path | Permission | Notes |
|---|---|---|---|
| GET | `/plans` | subscription.view | `{items: Plan[]}` |
| GET | `/tenants/:tenantId/subscriptions` | subscription.view | 404 unknown tenant |
| POST | `/tenants/:tenantId/subscriptions` | subscription.manage | `CreateSubscriptionRequest`; status `trial`/`active`; `validUntil > validFrom`; limits default from the plan; one non-cancelled subscription per tenant (409 `subscription_exists`); 409 `tenant_archived` |
| PATCH | `/subscriptions/:id` | subscription.manage | `UpdateSubscriptionRequest` (≥1 field); `cancelled` is terminal (409 `subscription_cancelled`) |
| GET | `/devices/:deviceId/entitlements` | subscription.view | history, never the token |
| POST | `/devices/:deviceId/entitlements/issue` | license.issue | 409 `no_active_subscription` / `device_not_enrolled` / `device_limit_reached` / `generation_conflict`; 503 `signing_key_*` |
| POST | `/devices/:deviceId/entitlements/renew` | license.renew | as issue, plus 409 `no_entitlement_to_renew` |
| POST | `/devices/:deviceId/entitlements/revoke` | license.revoke | `{reason}` 3–500 chars; revokes every live generation; 409 `no_active_entitlement` |
| GET | `/screens/subscriptions` | subscription.view | one D1 round trip beyond auth |
| GET | `/screens/subscriptions/:id` | subscription.view | one D1 round trip beyond auth |

Rules: "active subscription" = status `trial` or `active` **and** `valid_from ≤ now < valid_until`. Expiry (`active` / `expiring` within `renewal_warning_days` / `expired` / `scheduled` / `inactive`) and `daysRemaining` are derived at read time, never stored; tenant status is not written by this slice.

## Audit events (as built)

- `SUBSCRIPTION_CHANGED` — action `created` / `updated` / `cancelled`; full before/after subscription.
- `LICENSE_ISSUED`, `LICENSE_RENEWED` — entity `entitlement/lic_…`; after = record + signed claims (claims are not secret); the token is never audited.
- `LICENSE_REVOKED` — entity = newest revoked generation; before/after carry `deviceId`, `tenantId`, `generations`, `revokedAt`, typed `reason`.

## Tests

**Happy path:**
- Create subscription: select plan "Pro", valid_from=today, valid_until=today+365d
- Verify subscription appears in list with status "active"
- Edit subscription: extend valid_until to today+730d
- Verify audit event shows update
- Issue entitlement to Device A: call POST /api/v1/subscriptions/{sub_id}/issue-entitlement
- Verify entitlement_id assigned, generation=1, stored in D1

**Expiry scenario:**
- Create subscription with valid_until=today-1
- Verify status displays "expired" on admin console
- Device with this subscription should reject license (test in Slice 3.2)

**Offline grace:**
- Subscription has offline_grace_days=14
- Device offline for 10 days within grace window: allowed
- Device offline for 20 days beyond grace window: blocked by Agent (Slice 3.2)

## Demo path

```
Super Admin SaaS console:

1. Navigate to Tenant → Subscriptions
2. Click "New Subscription"
3. Select Plan: "Pro" (max_devices=5, max_managed_users=3)
4. Set valid_from=today, valid_until=today+1 year
5. Click Create
6. Verify subscription appears with status "active"
7. Refresh after 1 second
8. Click subscription row to see details
9. Click "Issue License" for an enrolled device
10. Verify entitlement_id generated, generation=1
11. Verify audit log: SUBSCRIPTION_CREATED, ENTITLEMENT_ISSUED
```
