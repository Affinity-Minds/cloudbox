# Slice 2.3 — One-time enrollment

## Goal

Super Admin generates a single-use enrollment token. A device running the Agent redeems the token with the public key and a one-time authorization code, binding the device to the tenant and appearing immediately in the Fleet table.

## Existing capabilities reused

- `enrollment_tokens` table from foundation migration 0003
- Crypto.getRandomValues for code generation
- SHA-256 hash-stored tokens (no plaintext at rest)
- Device identity + public key from Slice 2.2
- Fleet table listener (Phase 7, but stub in Phase 2)
- Audit service for enrollment events

## Data changes

**Schema (from foundation migration 0003):**
- `enrollment_tokens(id, tenant_id, token_hash UNIQUE, label, created_by, expires_at, redeemed_at, redeemed_device_id, created_at)`
- `devices(id 'dev_…', tenant_id, name, status, device_public_key_jwk, device_key_thumbprint UNIQUE, key_protection, hostname, windows_build, agent_version, last_seen_at, last_health_json, enrolled_at, revoked_at)`
- `device_credentials(id, device_id, token_hash UNIQUE, created_at, revoked_at)` — long-lived device bearer token after enrollment

**Token format:** `CBX-ENROLL-XXXX-XXXX` (8 random bytes, 4 groups of 2 hex chars separated by dash)

## Authorization

- Super Admin permission: `device.enroll` (implied by tenant admin via UI or API)
- Server-side: verify token not expired, not already redeemed, tenant matches
- Device: one-time use only

## Audit events

- `ENROLLMENT_TOKEN_CREATED` — token_id, tenant_id, created_by, expires_at, label
- `ENROLLMENT_TOKEN_REDEEMED` — token_id, device_id, device_public_key_thumbprint, enrolled_at
- `DEVICE_ENROLLED` — device_id, tenant_id, enrollment_by (system), device_name, status='enrolled'

## Tests

**Happy path:**
- Super Admin creates enrollment token via API or UI
- Token appears in list with label, expiry, unredeemed status
- Device runs setup with token
- Device sends POST /api/v1/agent/enroll with token + public key + device info
- Server verifies token hash, device_public_key_jwk, generates device_id
- Server returns device_id, tenant_id, tenant_code, device_token (bearer token)
- Device stores bearer token, appears in Fleet table within 1 minute
- Subsequent heartbeats use bearer token (Slice 2.3 client API)

**Failure paths:**
- Token cannot be redeemed twice (second attempt: 401)
- Expired token: 401
- Invalid token format: 400
- Mismatched tenant in request: 401 or 403

**Isolation test:**
- Device enrolled to Tenant A attempts to use Tenant B enrollment token: rejected
- Device enrolled to Tenant A cannot see Tenant B's fleet: 403

## Demo path

```
Super Admin UI or API:

1. Navigate to Tenant → Enrollment
2. Click "Create Token"
3. Enter label "Lab Windows Box"
4. Submit
5. Copy token: CBX-ENROLL-XXXX-XXXX
6. Share with operator (or use in setup.exe)

Device (Windows lab machine):

1. Run CloudBox.Server.Setup.exe
2. Prompted for enrollment token
3. Paste token
4. Setup launches Agent with token
5. Agent derives device public key (Slice 2.2)
6. Agent calls POST /api/v1/agent/enroll with token + public key
7. Server responds with device_id, device_token
8. Agent stores device_token, used for heartbeat

Admin dashboard:

9. Refresh Fleet table
10. New device appears with status "enrolled", online=true (after 1st heartbeat)
11. Verify audit log shows ENROLLMENT_TOKEN_REDEEMED + DEVICE_ENROLLED
```
