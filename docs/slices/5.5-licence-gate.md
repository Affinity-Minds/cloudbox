# Slice 5.5 (+ 3.3, 3.5) — Local verifier, licence gate, Status app

As built by WT-10. Spec §10, §12, §13, §31, §33. Format: `docs/slices/3.2-entitlement-format.md`.

## Local verifier (Slice 3.3, `apps/cloudbox-agent/Licensing/`)

`EntitlementVerifier.VerifyAsync(token, deviceRsa, devicePublicJwk, pinnedJwks)`, same order and codes as the TS
reference verifier: 5 segments → JWE header gate (`RSA-OAEP-256`/`A256GCM`, no `zip`, `cty JWT`) → decrypt with the CNG
device key → inner `ES256`, kid = outer kid, kid pinned → `JsonWebTokenHandler` (typ `cbx-entitlement+jwt`, issuer
`cloudbox`, no lifetime rules) → claim consistency → RFC 7638 thumbprint equals the local key.

**Library split, proved on windows-latest:** Microsoft.IdentityModel 8.23 cannot unwrap RSA-OAEP-256 (its RSA key-wrap
set is RSA1_5 / RSA-OAEP; test `IdentityModel_refuses_RSA_OAEP_256`), so only the decrypt step uses `jose-jwt` 5.3.0
(`JWT.Decode(token, rsa, RSA_OAEP_256, A256GCM)`); the JWS is verified by IdentityModel.

**Pinned keys:** fetched once at enrollment from `GET /api/v1/agent/signing-keys` (device Bearer, TLS) and stored in the
DPAPI state; re-fetched (additively, never removed) only when a lease names an unpinned kid (rotation, ADR 0004).

**Accepting a lease:** a downloaded generation replaces the stored one only after it verifies, names this device and
tenant, and is not older than the highest generation ever accepted.

**Evaluation** (`LicenseEvaluator`, pure) → `VALID | OFFLINE_VALID | GRACE | EXPIRED | TAMPER | REVOKED | NO_PLAN`:
device credential refused by the cloud → `REVOKED`; clock behind the trusted-time mark → `TAMPER`; no lease →
`NO_PLAN` with the cloud's message ("No active plan found. Please contact the CloudBox admin." / device limit); lease
fails verification, other device/tenant, or stale generation → `TAMPER`; cloud reports no live lease while one is held
→ `REVOKED`; then time = max(local clock, trusted high-water mark): ≤ `valid_until` → `VALID` (online) /
`OFFLINE_VALID`; ≤ `valid_until + offline_grace_days` → `GRACE`; else `EXPIRED`. Days remaining, grace days, renewal due
(`days ≤ renewal_warning_days`).

## Licence gate (Slice 5.5, `apps/cloudbox-agent/Gate/`)

- Rules (manifest): `CloudBox RDP Access` allow TCP 3389 in; `CloudBox RDP Gate` **block** TCP 3389 in, created enabled.
  Block wins. Remote scope any until WT-9 narrows both to the overlay.
- `VALID | OFFLINE_VALID | GRACE` → block rule disabled (open); anything else, unknown included → enabled (blocked).
- Fail closed: blocked at service start before validation and at service stop; watchdog task (SYSTEM, at boot and every
  minute) re-enables the block rule when the `CloudBoxAgent` service is not running; the service's own recovery policy
  restarts it in 5 s and it re-validates locally without the cloud.
- Never deletes the runtime, users or data; established sessions and the local console are unaffected.
- Published: pipe `gate: open | blocked | not_installed | error`; health `license: {state, days_remaining}`.

## Status app (Slices 2.4 / 3.5, `apps/cloudbox-status/`)

WPF, fixed-size, reads `\\.\pipe\CloudBoxAgent` every 5 s unelevated: server name + Tenant ID, cloud pill, licence state
and days remaining (or the no-plan message), grace/expired/revoked/tamper wording, users "Configured x / N" and "Active
sessions n" (separate concepts, spec §13), remote access state, private network placeholder, support-access banner
placeholder, agent version. Renewal QR (QRCoder) only while renewal is due, encoding only the public URL the Agent
publishes (`{base}/portal?renew={tenantCode}`, https only). Starts at logon of the parent account.
