# Slice 1.1 — Email OTP authentication

## Goal

Humans can securely authenticate to the CloudBox SaaS with email-based one-time passwords, establishing an httpOnly session that persists across page reloads and can be revoked via logout.

## Existing capabilities reused

- `better-auth` library with `emailOTP` plugin (maintained, no custom auth code)
- Drizzle ORM adapter on D1
- Cloudflare Email Service binding (`send_email`) for OTP delivery
- `@hono/zod-validator` for request validation
- `input-otp` React component for OTP input UI
- Tailwind v4 + shadcn/ui for UI styling
- TanStack Router for page navigation

## Data changes

**Migrations:** None in Phase 1 - Better Auth tables are generated by the `@better-auth/cli` during foundation setup.

**Schema (generated by better-auth):**
- `user` — managed by better-auth
- `session` — httpOnly cookies only, never exposed to client
- `account` — email provider linkage
- `verification` — OTP storage and validation state

## Authorization

- No authorization required to send OTP (anti-enumeration applies equally)
- Session established after successful OTP verification
- `/dashboard` and other protected routes require valid session

## Audit events

- `OTP_SENT` — email + timestamp, no secrets logged
- `OTP_VERIFIED` — email + device info (User-Agent), maps user to session
- `USER_LOGOUT` — user_id, session_id, timestamp

## Tests

**Happy path:**
- Send OTP to valid email
- Receive OTP in dev echo (OTP_DEV_ECHO=1) or inbox
- Verify OTP within validity window (10 min)
- Receive session cookie (httpOnly + Secure)
- Logout invalidates session

**Permission boundaries:**
- Invalid email: same response as invalid OTP (no enumeration)
- Expired OTP: rejected with generic "invalid OTP" message
- Reused OTP: rejected (single-use)
- Rate limits: 6 OTP sends per email per hour; 3 verify attempts per OTP

**Failure paths:**
- OTP service unavailable: friendly error, retry available
- Email delivery failure: logged but user sees "check email"

## Demo path

```
1. Navigate to https://staging-url/login
2. Enter email "test@example.com"
3. Check email or developer console for OTP
4. Enter OTP on verification screen
5. Redirect to /dashboard with session cookie
6. Verify session persists on page reload
7. Click logout
8. Verify session cookie removed, redirect to /login
```
