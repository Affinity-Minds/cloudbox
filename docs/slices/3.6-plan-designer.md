# Slice 3.6 — Plan designer, plan selector, timezone selector

## Goal

Plans stop being a seed row nobody can change: staff can create, edit, retire and reactivate
plans through an operational console, with a lifecycle (`active`/`retired`) that keeps existing
subscriptions working while stopping a retired plan from being chosen again. Two reusable
comboboxes (plan picker, timezone picker with search) replace the plain text inputs the tenant
sheet and subscription dialog used before.

## Existing capabilities reused

- `plans` table (foundation migration 0003) — extended, not replaced
- WT-5's plans router (`GET /api/v1/plans`) and `toPlan`/`toSubscription` mappers
- WT-1's `requirePermission` staff gate
- `audit()` service
- shadcn `Command` (already installed); `Popover` added this slice (`pnpm dlx shadcn add popover`,
  no new dependency — the underlying `radix-ui` package already ships it)

## Data changes (migration `0009_plans_lifecycle.sql`)

`plans` gains, all backward compatible (existing `cloudbox-6` row backfilled in the same
migration):

- `description TEXT` (nullable)
- `status TEXT NOT NULL DEFAULT 'active'`, `CHECK(status IN ('active','retired'))` — D1/SQLite
  cannot add a CHECK via `ALTER TABLE`, so it is enforced with `BEFORE INSERT`/`BEFORE UPDATE`
  triggers (the same idiom migration 0002 uses for `audit_log`'s append-only guard)
- `term_days INTEGER NOT NULL DEFAULT 365`, `CHECK(term_days BETWEEN 1 AND 3650)` — days a
  redeemed subscription runs (owner addition, mid-slice). **The redemption semantics — a
  subscription is `pending` until the tenant's first server activates, at which point
  `valid_from = now`, `valid_until = now + term_days`, and the device licence is issued — belong
  to WT-14 (`slice 2.6`), not this one; this slice only carries the column and its UI.**
- `created_at`, `updated_at` (ISO-8601 UTC text, same convention as every other table)

`code` stays the primary key and is immutable — accepted only on create, never in the update
schema.

## Authorization (as built)

- Reads of **active** plans: `subscription.view` (unchanged from WT-5 — `GET /plans`).
- Reads of **retired** plans (`GET /plans?include=retired`) and every write (create, update,
  retire, reactivate): `subscription.manage`.
- `GET /screens/plans` (the designer's own table, which shows retired plans too): gated
  `subscription.manage`.

## API (as built, `/api/v1`)

| Method | Path | Permission | Notes |
|---|---|---|---|
| GET | `/plans` | subscription.view | active plans only (unchanged shape, additive fields) |
| GET | `/plans?include=retired` | subscription.manage | every plan |
| POST | `/plans` | subscription.manage | `CreatePlanRequest`; code slug `^[a-z0-9-]{3,32}$`; 409 on duplicate code |
| PATCH | `/plans/:code` | subscription.manage | `UpdatePlanRequest` (≥1 field, no `code`, no `status`); 404 unknown |
| POST | `/plans/:code/retire` | subscription.manage | 404 unknown; 409 `already_retired`; returns `{plan, subscriptionCount}` |
| POST | `/plans/:code/reactivate` | subscription.manage | 404 unknown; 409 `already_active`; returns `{plan, subscriptionCount}` |
| GET | `/screens/plans` | subscription.manage | `PlansScreen`: every plan + subscription count, one `db.batch` round trip beyond auth |

Rules: a retired plan cannot be chosen for a **new** tenant (`POST /tenants`, or `PATCH /tenants/:id`
setting `planCode`) or a **new** subscription (`POST /tenants/:tenantId/subscriptions`) — 409
`plan_retired` in both places. An existing subscription already on a plan that gets retired later
is untouched: it keeps its dates, status and entitlements exactly as before. There is no DELETE
route — a plan is never deleted, only retired.

### Server-side timezone validation

`CreateTenantRequest`/`UpdateTenantRequest`'s `timezone` field was always free text; this slice
adds a runtime check in `tenants.ts` — `Intl.supportedValuesOf('timeZone').includes(tz)`, with a
`Intl.DateTimeFormat` probe fallback for a runtime without `supportedValuesOf` (verified present
in the `@cloudflare/vitest-pool-workers` test pool) — returning `400 {"error":"invalid_timezone"}`
on an unknown zone, on both create and update.

## Audit events (as built)

- `PLAN_CREATED` — before `null`, after the full plan.
- `PLAN_UPDATED` — before/after the changed fields (whole plan row shape).
- `PLAN_RETIRED` / `PLAN_REACTIVATED` — before/after `status`; the response also carries
  `subscriptionCount` so the UI's confirmation names how many subscriptions are affected (none —
  they keep working).

## UI (as built)

- `routes/_app/plans.tsx` — operational table (code, name, devices, users, features as pills,
  grace, warning, term, status pill, subscription count), New plan / Edit in a sheet
  (`components/plan-form-sheet.tsx`, react-hook-form + shadcn `Field`, nothing written until
  Save), Retire/Reactivate per row opens `components/retire-plan-dialog.tsx` naming the exact
  subscription count. Honest empty state when there are no plans yet.
- `components/plan-select.tsx` — combobox (`Popover` + `Command`): lists **active** plans from
  `GET /plans` via TanStack Query (cached, `staleTime: 60s`), searchable by code or name, shows
  "N devices · M users" as the secondary line, and — critically — still shows the current value
  even when that plan has since been retired, marked "(retired)" so nothing is silently hidden.
  Used in the tenant create/edit sheet and the subscription create dialog (additive replacement of
  its plan field only; the rest of that dialog is unchanged).
- `components/timezone-select.tsx` (+ `lib/timezones.ts`, split out so the matching logic is
  unit-testable without mounting React) — combobox over every
  `Intl.supportedValuesOf('timeZone')` zone (bundled fallback list otherwise), grouped by IANA
  region, searchable by substring (`"asia/"`, `"kolkata"`) or a small hand-picked abbreviation map
  for the ~40 most-selected zones (`"ist"`, `"est"`, `"pacific"`, …), each row showing its current
  UTC offset computed live via `Intl.DateTimeFormat`. Defaults to the browser's own zone when
  creating a tenant. Used in the tenant sheet and (owner request, mid-slice) `/start`'s
  organisation step, replacing that page's plain `<select>` so there is one timezone selector
  everywhere.
  - **Runtime quirk found while building this**: depending on the ICU database bundled with the
    runtime, `Intl.supportedValuesOf('timeZone')` can return a legacy alias instead of the modern
    canonical name for the same zone — this environment's Node/Chromium list `Asia/Calcutta`, not
    `Asia/Kolkata` (both name the same real-world zone; nothing here is wrong, ICU vintage just
    differs by build). The search matches either spelling regardless of which one the runtime
    actually exposes (`lib/timezones.ts`'s `LEGACY_ALIAS_PAIRS`/`ZONE_SYNONYMS`), and the display
    honestly shows whichever name the runtime returned rather than silently rewriting it.

## Tests

Workers pool (`apps/worker-api/test/plans.test.ts`, 19 tests): plan CRUD (create, validation
including the code slug and every numeric bound, duplicate code, immutable code on PATCH, PATCH
requires ≥1 field); retire/reactivate lifecycle (blocks a new tenant, blocks a new subscription,
**does not disturb an existing subscription already on the plan** — it stays readable and
PATCH-able — cannot set a retired plan on a tenant PATCH either, retiring twice is 409 not a
silent 200, reactivate un-blocks selection, unknown code 404s, the default `GET /plans` excludes a
retired plan while `?include=retired` includes it); permission boundary (anonymous 401 on every
route, `read_only` can read active plans but not retired and cannot write any of the five write
routes); `GET /screens/plans` round-trip ceiling via `countingD1` (`≤ 1 + AUTH_ROUND_TRIPS`) with a
real subscription count; invalid/valid IANA timezone on tenant create and update. The loader's
query is registered in `test/queries.ts` (`screens.plans: subscription count grouped by plan_code`)
and passes the existing unindexed-scan guard.

admin-web (`src/lib/timezones.test.ts`, 8 tests): substring matching including a region prefix,
abbreviation matching case-insensitively, an abbreviation belonging to a different zone does not
match, empty query matches everything, no match returns false, region splitting, and the
legacy-alias case (`Asia/Calcutta` found by searching "kolkata" and vice versa).

## Demo path

```
Staff console (super_admin):

1. Govern → Plans: seeded cloudbox-6 only, honest table
2. New plan → cloudbox-pro, 10 devices, 25 users, all three features, 14d grace, 45d warning,
   365d term → Save → appears in the table, status "active"
3. Retire cloudbox-pro → confirmation names "No subscriptions are on this plan right now" →
   Retire plan → status pill flips to "retired"
4. Reactivate → status flips back to "active"
5. Tenants → New tenant → Plan combobox: type "clo" → both plans listed with device/user counts →
   pick CloudBox 6
6. Timezone combobox: type "kolk" → matching zone(s) shown grouped under "Asia", with live UTC
   offset → pick it → Save → tenant created with both fields set
```
