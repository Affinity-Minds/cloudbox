# Slice 3.2 — Standard signed/encrypted entitlement format

## Goal

The server issues machine-bound entitlements as ES256-signed JWS claims, encrypted to the device's public key using RSA-OAEP-256/A256GCM JWE. Only the enrolled device can decrypt and verify.

## Existing capabilities reused

- `jose` library (ES256 signing + RSA-OAEP-256/A256GCM encryption)
- Device public key from Slice 2.2
- Signing keys infrastructure from foundation (spec §7)
- Private signing key stored in Wrangler secret `ENTITLEMENT_SIGNING_JWK`
- .NET `System.IdentityModel.Tokens.Jwt` on device for verification

## Data changes

**Schema (from foundation migration 0003):**
- `signing_keys(kid PK, alg, public_jwk, status CHECK('active','retired'), created_at)`
  - Master key seeded during bootstrap; rotation adds new rows
- `entitlements` already has `token` field (TEXT, compact JWE)

## Authorization

- Issuance: `subscription.manage` + `device.manage`
- Retrieval by device: Bearer device_token (from Slice 2.3)
- Server verification: public kid from `signing_keys` table (rotate-friendly)

## Entitlement payload (claims)

```json
{
  "iss": "cloudbox",
  "aud": "device",
  "kid": "<signing_key_id>",
  "device_id": "dev_XXXXX",
  "device_thumbprint": "<SHA-256 of device public key>",
  "subscription_id": "sub_XXXXX",
  "generation": 1,
  "issued_at": 1695043200,
  "valid_from": 1695043200,
  "valid_until": 1726665600,
  "max_managed_users": 3,
  "max_devices": 5,
  "features": ["rpc_access", "backup", "update"],
  "offline_grace_days": 14,
  "claims_version": "1.0"
}
```

**JWS + JWE flow:**

1. Claims serialized to JSON
2. Signed with ES256 (private signing key from secret)
3. Resulting JWS encrypted to device public key (RSA-OAEP-256)
4. Encrypted to A256GCM (compact JWE serialization)
5. Stored in `entitlements.token` (TEXT)
6. Never logged, never printed, never exposed to UI

## Device verification (.NET on Windows)

1. Decrypt JWE with device private key (TPM or software from Slice 2.2)
2. Extract JWS payload
3. Verify ES256 signature with server public key (pinned in config or fetched once)
4. Verify `device_id` and `device_thumbprint` match local device
5. Verify `valid_until` vs. trusted time (Slice 4.1)
6. Verify `issued_at` is recent (anti-replay)
7. Fail closed if any verification fails

## Tests

**Happy path:**
- Issue entitlement to Device A
- Retrieve via GET /api/v1/agent/entitlement (Bearer device_token_a)
- Parse JWE in device test harness
- Verify ES256 signature
- Verify device_thumbprint matches enrolled key
- Verify claims are present and valid

**Negative tests:**
- Entitlement copied to Device B
  - Device B decrypts: gets payload
  - Device B verifies device_thumbprint: MISMATCH
  - License validation fails, Device B denied
- Entitlement modified in transit
  - Device detects JWE tampering
  - Decryption fails or MAC fails
- Entitlement from Device A, retrieved by Device B
  - Device B has different bearer token
  - Server returns 404 (not found for this device)

**Key rotation:**
- Signing key marked retired in `signing_keys`
- Old entitlements still valid (kid in header)
- New entitlements signed with active key

## Demo path

```
Server (issuance):

1. POST /api/v1/subscriptions/{sub_id}/issue-entitlement
   body: { device_id: "dev_ABC", }
2. Response: { entitlement_id: "lic_XYZ", device_id: "dev_ABC" }
3. Check database: entitlements.token is non-null JWE string

Device (verification):

4. GET /api/v1/agent/entitlement (Bearer device_token_abc)
5. Response: { entitlement: "<compact-jwe>", generation: 1 }
6. Agent decrypts with TPM/CNG private key
7. Verifies ES256 signature
8. Parses claims:
   - device_id matches
   - device_thumbprint matches
   - valid_until in future
9. Logs (non-secret): "License valid until 2024-12-31"
10. Stores entitlement for offline use (Slice 3.3)

Adversary scenario:

11. Copy Device A's entitlement.jwe to Device B
12. Device B decrypts (works, RSA public key not secret)
13. Device B verifies signature (works)
14. Device B verifies device_thumbprint: MISMATCH (Device B's thumbprint != Device A's)
15. License rejected, Device B denied access
```
