# Slice 3.2 — Standard signed/encrypted entitlement format

## Goal

The server issues machine-bound entitlements as ES256-signed JWS claims, encrypted to the device's public key as an RSA-OAEP-256/A256GCM JWE. Only the enrolled device can decrypt and verify. Decision record: ADR 0004.

## Status (WT-5, cloud side)

Built: issuer, reference verifier, key generator, issuance/renew/revoke API, test vector. The Windows verifier (WT-4 / WT-10) and `GET /api/v1/agent/entitlement` (WT-3) consume this contract.

## Existing capabilities reused

- `jose` 6.2.12 (`SignJWT`, `CompactEncrypt`, `compactDecrypt`, `jwtVerify`, `calculateJwkThumbprint`, `generateKeyPair`); no hand-rolled cryptography
- Device RSA public key from Slice 2.2/2.3 (`devices.device_public_key_jwk`, thumbprint `devices.device_key_thumbprint`, RFC 7638)
- `signing_keys` table and `entitlements.token` column from foundation migration 0003
- Private signing key in Wrangler secret `ENTITLEMENT_SIGNING_JWK` (runbook: `docs/runbooks/licensing-key-rotation.md`)

## Envelope (as built)

```
claims ──SignJWT──▶ JWS compact   protected header {"alg":"ES256","kid":"<kid>","typ":"cbx-entitlement+jwt"}
       ──CompactEncrypt──▶ JWE compact   protected header {"alg":"RSA-OAEP-256","enc":"A256GCM","cty":"JWT","kid":"<kid>"}
```

- `<kid>` is the RFC 7638 SHA-256 thumbprint (base64url) of the server's P-256 public key; the same value appears in both headers and in the `kid` claim.
- The JWE plaintext is the UTF-8 bytes of the compact JWS.
- Stored in `entitlements.token`; never logged, never audited, never returned to the admin UI. Only `GET /api/v1/agent/entitlement` (device bearer token, WT-3) serves it.

## Claims (as built; `@cloudbox/contracts` `EntitlementClaims`, `@cloudbox/licensing-contracts` `EntitlementClaims`)

```json
{
  "iss": "cloudbox",
  "kid": "<server kid, equals JWS header kid>",
  "jti": "lic_…",
  "iat": 1790449401,
  "license_id": "lic_…",
  "tenant_id": "ten_…",
  "device_id": "dev_…",
  "device_key_thumbprint": "<RFC 7638 SHA-256 base64url of the device RSA public JWK>",
  "max_managed_users": 6,
  "valid_from": "2026-09-26T19:03:21.063Z",
  "valid_until": "2027-09-26T00:00:00.000Z",
  "renewal_warning_days": 30,
  "offline_grace_days": 7,
  "generation": 1,
  "features": ["remote_access", "managed_backup", "fleet"]
}
```

- `jti` equals `license_id`. `iat` is seconds since the epoch. `valid_*` are ISO-8601 UTC.
- **No `exp` / `nbf`**, deliberately: validity and offline grace are evaluated by the agent against its trusted-time high-water mark (spec §10, §11), so a JWT library must not apply its own wall-clock rules. Disable lifetime validation in the verifier.
- `valid_until` = min(requested, subscription `valid_until`). `generation` = max+1 per device (`UNIQUE(device_id, generation)`).

## Reference verifier (TypeScript)

`verifyEntitlement({ token, devicePrivateJwk, serverPublicJwks })` in `packages/licensing-contracts/src/entitlement.ts`. Order of checks, each failure an `EntitlementError` with `code`:

1. Token has 5 segments (`malformed`).
2. JWE header: `alg == "RSA-OAEP-256"`, `enc == "A256GCM"`, no `zip` (`unsupported_algorithm`); `cty == "JWT"` (`malformed`).
3. Decrypt with the device key, restricted to exactly those algorithms (`decryption_failed`).
4. JWS header: `alg == "ES256"` (`unsupported_algorithm`); `kid` present, equal to the JWE `kid`, and in the pinned set (`unknown_kid`).
5. `jwtVerify(jws, pinnedKey, { algorithms: ["ES256"], issuer: "cloudbox", typ: "cbx-entitlement+jwt", requiredClaims })` (`signature_invalid` / `claims_invalid`).
6. `claims.kid == header kid`, `jti == license_id`, `generation` a positive integer (`claims_invalid`).
7. `device_key_thumbprint == RFC7638(local device public key)` (`device_mismatch`).

Then the agent (not the format) checks: `device_id` matches local state, `generation >= highest stored`, `valid_until` (+ `offline_grace_days`) against trusted time.

## .NET verification (WT-4 / WT-10)

Same order, same fail-closed rule. Packages: `Microsoft.IdentityModel.JsonWebTokens` + `Microsoft.IdentityModel.Tokens` (8.x). The device key is an `RSACng` over the TPM key (Microsoft Platform Crypto Provider) or the DPAPI-protected software key; the private operation never leaves CNG.

```csharp
using Microsoft.IdentityModel.JsonWebTokens;
using Microsoft.IdentityModel.Tokens;

// Pinned server keys: public JWKs from signing_keys (kid = RFC 7638 thumbprint), shipped in the agent.
IList<SecurityKey> pinned = pinnedJwkJson.Select(j => (SecurityKey)new JsonWebKey(j)).ToList();
var deviceKey = new RsaSecurityKey(rsaCng);  // RSACng for the enrolled key

// 1–2. Header gate before any cryptography.
var outer = new JsonWebToken(token);               // parses the 5-part JWE header
if (outer.Alg != "RSA-OAEP-256" || outer.Enc != "A256GCM"
    || !string.Equals(outer.Cty, "JWT", StringComparison.OrdinalIgnoreCase)
    || outer.TryGetHeaderValue<string>("zip", out _))
    return Reject("unsupported_algorithm");

// 3–5. Decrypt the JWE and verify the nested ES256 JWS against the pinned kid.
var result = await new JsonWebTokenHandler().ValidateTokenAsync(token, new TokenValidationParameters
{
    TokenDecryptionKey = deviceKey,
    IssuerSigningKeys = pinned,
    TryAllIssuerSigningKeys = false,                    // kid must name a pinned key → else unknown_kid
    ValidAlgorithms = new[] { SecurityAlgorithms.EcdsaSha256 },   // "ES256" only
    ValidTypes = new[] { "cbx-entitlement+jwt" },
    ValidIssuer = "cloudbox",
    ValidateAudience = false,
    ValidateLifetime = false,                           // no exp: trusted-time logic decides (§10, §11)
    RequireExpirationTime = false,
    RequireSignedTokens = true,
});
if (!result.IsValid) return Reject(result.Exception);  // decryption_failed / signature_invalid / unknown_kid
var jws = ((JsonWebToken)result.SecurityToken).InnerToken;   // the verified JWS

// 4, 6. Header/claim consistency.
if (jws.Alg != "ES256" || jws.Kid != outer.Kid) return Reject("unknown_kid");
if (jws.GetClaim("kid").Value != jws.Kid || jws.GetClaim("jti").Value != jws.GetClaim("license_id").Value)
    return Reject("claims_invalid");

// 7. Bound to THIS device key (RFC 7638 over kty, n, e).
var local = JsonWebKeyConverter.ConvertFromRSASecurityKey(new RsaSecurityKey(rsaCng.ExportParameters(false)));
var thumb = Base64UrlEncoder.Encode(local.ComputeJwkThumbprint());
if (jws.GetClaim("device_key_thumbprint").Value != thumb) return Reject("device_mismatch");
```

**Confirm on the `windows-latest` runner:** support for `RSA-OAEP-256` key unwrap and `A256GCM` content decryption in the pinned Microsoft.IdentityModel version. The acceptance test is the committed vector (below). If the handler answers "algorithm not supported" (IDX10715-class errors) for either, keep the header gate and replace only the decrypt step with the standard `jose-jwt` package (MIT), then verify the JWS with `JsonWebTokenHandler` as above without `TokenDecryptionKey`:

```csharp
string jwsCompact = Jose.JWT.Decode(token, rsaCng, JweAlgorithm.RSA_OAEP_256, JweEncryption.A256GCM);
```

Do not implement RSA-OAEP or AES-GCM framing by hand.

## Authorization

- Issue `license.issue`, renew `license.renew`, revoke `license.revoke` (seed: super_admin all three; admin issue + renew; support/read_only none). History `subscription.view`.
- Retrieval by device: Bearer device token (ADR 0005, WT-3).

## Tests

`packages/licensing-contracts/test/entitlement.test.ts` (node): round trip, one-character tamper in each of the five JWE segments, encrypt to A / decrypt with B, re-encrypted-to-B thumbprint mismatch, forged signature under a pinned kid, stale kid (pinned → trusted, unpinned → `unknown_kid`), HS256 / ES384 inner JWS, RSA-OAEP / A128GCM outer JWE, wrong `typ`, issuer refuses inconsistent `kid`/`iss`/`jti`. `apps/worker-api/test/subscriptions.test.ts` (workerd + D1): the stored token decrypts to the response claims with the device key.

## Demo path (local)

1. `wrangler dev` with `.dev.vars` holding a dev `ENTITLEMENT_SIGNING_JWK` (from `generate-signing-key.ts`).
2. Seed a tenant + device (device RSA key generated locally), create a `cloudbox-6` subscription and `POST /devices/:id/entitlements/issue` through the API.
3. `node packages/licensing-contracts/scripts/inspect-entitlement.ts device-private.jwk.json server-public.jwk.json < entitlement.jwe` prints the claims; the same token with another device's key prints `rejected: decryption_failed`.
