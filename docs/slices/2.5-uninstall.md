# Slice 2.5 — Uninstall to original state

## Goal
An owner can remove CloudBox from a machine with one command (or Apps & Features) and prove with `verify-clean`
that nothing CloudBox created remains and every changed setting is back to its prior value.

## Existing capabilities reused
- `sc.exe` (create/failure/delete), `ServiceController`, `netsh advfirewall`, `net user` / `net localgroup`,
  `schtasks`, `EventLog.CreateEventSource/DeleteEventSource`, `CngKey.Delete`, `Microsoft.Win32.Registry`,
  `ProtectedData` (DPAPI machine scope) for the manifest backup.
- Windows Apps & Features (ARP) `UninstallString`.

## Data changes
- `C:\ProgramData\CloudBox\install-manifest.json` and DPAPI copy `HKLM\SOFTWARE\CloudBox\ManifestBackup\Manifest`.
- `%TEMP%\CloudBox-uninstall-report.json` written by uninstall (evidence; the only file left, outside CloudBox folders).
- No cloud migration (WT-3 owns `POST /api/v1/agent/uninstalled`).

## API/contracts
- Manifest entry `{kind, id, createdAt, priorState}` (+ additive `spec`, `status: pending|applied`), PLAN_5AM §10.
- `POST /api/v1/agent/uninstalled` with `Authorization: Bearer <deviceToken>`, no body, best effort.
- CLI: `uninstall [--purge-data] [--keep-logs] [--offline]`, `verify-clean` (exit 0/1).

## Authorization
- CLI verbs require elevation (`requireAdministrator` manifest plus an explicit check).
- `--purge-data` requires typing the machine name; refusal changes nothing.
- Cloud side (WT-3): device token only; marks the device revoked and audits `DEVICE_UNINSTALLED`.

## UI/Agent behavior
- Per-entry report: `removed`, `restored`, `missing`, `scheduled`, `failed`.
- Install failure rolls back automatically through the same path.
- Orphan cleanup when manifest and backup are both lost.

## Audit/events
- Cloud: `DEVICE_UNINSTALLED` (WT-3).
- Local: `SECURITY` channel for purge-data confirm/refuse.

## Tests
- `ManifestTests`: reverse-order revert with prior values restored; entry recorded before acting so a failed install
  is cleaned; verify-clean fails while an entry remains; orphan cleanup; purge refused without the typed name (empty
  and wrong name); purge proceeds with the name; data untouched without `--purge-data`; cloud notify best effort and
  skipped offline; every contract kind has a Windows step; manifest JSON carries the contract fields.
- `WindowsIntegrationTests` (CI runner): real directory/file/registry value/windows setting/registry key apply → revert
  → verify-clean, idempotent second revert; running exe scheduled for self-delete.
- Physical (owner, lab PC): `docs/runbooks/agent-install-dev.md` steps 9–11.

## Demo path
`docs/runbooks/agent-install-dev.md` steps 3 → 9 → 10 → 11.

## Rollback
Uninstall is itself the rollback. If uninstall has a bug, the manifest JSON lists every change with its prior state
for manual restoration.
