# Slice 5.2 — RDP runtime health adapter

As built by WT-10. Decision: ADR 0012. Operations: `docs/runbooks/rdp-runtime.md`.

## Goal

The Agent reports the remote-session runtime as one normalised state, so SaaS and UI never depend on upstream file
names, and support can repair it without customer involvement.

## Contract

`IRdpRuntime` (`apps/cloudbox-agent/Rdp/RdpRuntime.cs`):

- `Probe()` → `RdpProbeResult(State, Listener, Detail)`, `State ∈ healthy | wrapper_missing | service_stopped |
  listener_missing | unsupported_runtime | repair_required`, evaluated in this order from an `IRdpSystem` seam:
  1. not x64 / not Windows 10+ → `unsupported_runtime`
  2. TermService missing or not hosted in `svchost.exe` → `unsupported_runtime`
  3. ServiceDll missing or `termsrv.dll` → `wrapper_missing`; `rdpwrap.dll` or any other DLL → `unsupported_runtime`
  4. `TermWrap.dll` or `zydis.dll` missing → `repair_required` (antivirus quarantine is the usual cause)
  5. TermService not running → `service_stopped`
  6. no TCP listener on `RDP-Tcp\PortNumber` (default 3389) → `listener_missing`
  7. otherwise `healthy`
- `Repair()`: `service_stopped` → start TermService; `wrapper_missing`/`repair_required` → re-run the retained package
  (`-install -offline`, verified); package missing → explains that Setup must be run again. Returns the new probe.

Published in the §29 health document as `rdp: {state, listener}` every heartbeat, and on the pipe as
`rdp: {state, listener, detail}` (Status app). `CloudBox.Agent.exe repair` runs `Repair()` when the manifest holds the
`rdp-runtime` component.

## Install/uninstall (manifest `third_party_component rdp-runtime`)

`RdpRuntimeComponent` → `RdpWrapperRuntime.Install/Uninstall`: kill stray instances, run with `-offline` last, 120 s
timeout, exit code ignored, verified through the registry (TermWrap + DLL + TermService running within 30 s; uninstall:
ServiceDll back to `termsrv.dll`, TermService restarted). Presence (for prior state and verify-clean) = ServiceDll is
TermWrap **or** `C:\Program Files\RDP Wrapper` exists. A wrapper that existed before Setup is prior state and is left
alone by uninstall.

## Tests

`RdpProbeTests` (every state from faked registry/service/listener/file inputs, quarantine → `repair_required`, repair
starts a stopped service and reports a missing package); `WindowsServerIntegrationTests.Rdp_probe_reads_the_runner…`
(real registry/service/listener reads on `windows-latest`: `wrapper_missing`).

## Not proven without hardware

The runtime itself (install, two concurrent sessions, uninstall back to `termsrv.dll`) — owner lab run.
