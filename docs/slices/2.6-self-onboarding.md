# Slice 2.6 — Self-service onboarding, device self-activation, plan redemption, Connect sign-in

As built by WT-14 (`wt/p2-self-onboarding`). Decision record: ADR 0011.

## Goal

A buyer signs up alone at `/start`, creates their organisation (or redeems a licence key from a
store), and activates their own server from the Setup app. The plan starts when the first server
activates; there is no trial. CloudBox Connect signs members in with Tenant ID + email + code.

## Existing capabilities reused

- Customer Better Auth instance and its hooks, limits and counters (WT-1): the start and Connect
  flows are the same instance (`flow: "start" | "connect"`), not new auth.
- Turnstile siteverify (`auth/challenge.ts`, WT-1).
- Tenant code counter (same statement as WT-2's), owner-membership row shape (WT-2).
- Enrollment tokens and `/agent/enroll` (WT-3), unchanged token format.
- Entitlement issuance `issueForDevice` and `currentEntitlementForDevice` (WT-5).
- `loadFleet` (WT-3) for the Connect device list; `getActiveTenantId` (WT-2).

## Data changes (migration 0010)

- `subscriptions`: status `pending`; `valid_from`/`valid_until` nullable; CHECK dates unless pending.
- `license_keys(id, batch_id, code_hash UNIQUE, code_last4, plan_code, batch_label, status, created_by,
  created_at, expires_at, redeemed_at, redeemed_tenant_id, redeemed_by_email, revoked_at, revoke_reason)`.

## API

| Method | Path | Gate | Notes |
|---|---|---|---|
| POST | `/api/auth/start/send-code` | Turnstile always | `{email}` → `{success:true}`; sends to any address |
| POST | `/api/auth/start/verify` | Turnstile always | `{email, code}` → session; creates the customer row once (`CUSTOMER_SIGNUP`) |
| POST | `/api/auth/connect/send-code` | none (closed) | `{tenantCode, email}` → `{success:true}` always; code only for active members |
| POST | `/api/auth/connect/verify` | none (closed) | `{tenantCode, email, code}` → `{token, user, tenantId, tenantCode}`; else the wrong-code body |
| GET | `/api/v1/onboarding/config` | public | `{turnstileSiteKey}` |
| GET | `/api/v1/onboarding/overview` | customer | tenants with standing, device count, plan state |
| POST | `/api/v1/onboarding/tenants` | customer | `{displayName, timezone}` → 201 `{tenantId, tenantCode}` |
| POST | `/api/v1/onboarding/redeem` | customer | `{code, displayName, timezone}` → 201 `{tenantId, tenantCode}`; 400 `invalid_license_key` |
| POST | `/api/v1/onboarding/activation-grants` | customer, Owner/Admin of `tenantId` | → 201 `{grant, enrollmentTokenId, tenantId, tenantCode, expiresAt}` (15 min) |
| GET | `/api/v1/connect/devices?tenantId=` | customer, active member | devices + online + licence state + plan |
| POST | `/api/v1/license-keys/batches` | `license.issue` | `{planCode, quantity ≤ 500, batchLabel, expiresAt?}`; JSON or `Accept: text/csv` |
| GET | `/api/v1/license-keys?batch=&status=&last4=` | `license.issue` or `subscription.view` | batches + keys, never code/hash |
| POST | `/api/v1/license-keys/:id/revoke` | `license.revoke` | `{reason}` |
| POST | `/api/v1/agent/enroll` | enrollment token | response gains optional `licenseState`, `message` |
| POST | `/api/v1/agent/heartbeat` | device token | response gains optional `licenseState`, `message`; auto-issues |
| POST | `/api/v1/tenants/:id/subscriptions` | `subscription.manage` | no dates → `pending` (plan assignment); dates → immediate override |

## Setup app (WT-10) call sequence

```
1. POST /api/auth/email-otp/send-verification-otp {email, type:"sign-in"}         (existing owner)
   or POST /api/auth/start/send-code {email} + x-cloudbox-turnstile                 (new owner)
2. POST /api/auth/sign-in/email-otp {email, otp}    or  POST /api/auth/start/verify {email, code}
   → cbx_session cookie (send Origin: https://box.affinity.ai.in on every POST)
3. GET  /api/v1/onboarding/overview → pick the tenant (standing owner/admin)
   (new owner: POST /api/v1/onboarding/redeem {code, displayName, timezone}
               or POST /api/v1/onboarding/tenants {displayName, timezone})
4. UI: "Activate this machine as a server for tenant CBX-xxxxx? Are you sure?"
5. POST /api/v1/onboarding/activation-grants {tenantId, deviceLabel: <hostname>} → {grant}
6. CloudBox.Agent.exe install --enroll-token <grant>
   → agent: POST /api/v1/agent/enroll → {…, licenseState, message?}
7. agent heartbeats: licenseState "licensed" → GET /api/v1/agent/entitlement;
   "no_active_plan" → show message; keep heartbeating (a plan attached later is issued automatically)
```

## Connect (WT-11) call sequence

```
1. POST /api/auth/connect/send-code {tenantCode, email}          → 200 {success:true} (always)
2. POST /api/auth/connect/verify {tenantCode, email, code}       → 200 {token, user, tenantId, tenantCode}
   (keep the cbx_session cookie; wrong anything → 400 {code:"INVALID_OTP", message:"Invalid OTP"})
3. GET  /api/v1/connect/devices                                  → ConnectDevicesResponse
```

## UI

- Customer surface: `/start` (email → code → organisation / licence key; Turnstile widget always
  shown), `/portal` tenant cards (Tenant ID "give this to your team", plan-state banner).
- Staff console: `Licence keys` (batches, keys, Generate dialog with keys shown once + Copy + CSV,
  revoke with typed reason); Fleet detail License tab gains a read-only "Tenant plan" line;
  Subscriptions show `pending activation`.
