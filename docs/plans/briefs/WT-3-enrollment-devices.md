# WT-3 — Enrollment tokens, device registry, Agent API, fleet table (Slice 2.3 cloud side + 7.3-lite)
Model: **Sonnet 5**. Branch: `wt/p2-enrollment` from `phase-1/identity` (after foundation). Reserved migration: `0006`.

Load: agent-notes `platform/fast-data-hydration.md`, `platform/cloudflare-workers.md` entries 7–10 and "SQLite unique indexes do not see NULLs", `design/ux-patterns.md` "Tables for operations".

You own: `apps/worker-api/src/routes/v1/enrollment.ts`, `devices.ts`, `agent.ts`, `apps/worker-api/src/screens/fleet.ts`, `apps/worker-api/src/devices/**`, `apps/admin-web/src/routes/_app/fleet.tsx`, `_app/fleet.$deviceId.tsx`, `_app/enrollment.tsx`, `apps/admin-web/src/api/devices.ts`. Contract files `packages/contracts/enrollment.ts`, `devices.ts`, `agent-health.ts` are fixed by the foundation; if you must change a field, request WT-0 and tell WT-4 in your handoff (they implement the Windows side of the same contract).

Deliver:
1. Enrollment tokens: `POST /api/v1/tenants/:id/enrollment-tokens {label, ttlMinutes≤1440}` gated `device.manage` or tenant standing `admin`. Generate `CBX-ENROLL-XXXX-XXXX` (Crockford base32 from `crypto.getRandomValues`, no ambiguous chars), store **only** SHA-256 hash, return plaintext once. `GET` list (label, created by, expires, redeemed/device), `DELETE` (revoke unredeemed). Audited `ENROLLMENT_TOKEN_CREATED/REVOKED`.
2. `POST /api/v1/agent/enroll` (unauthenticated, rate-limited per IP via Durable-Object-free approach: a `settings`-style counter is fine tonight; note the upgrade). Validate body against `contracts/enrollment.ts`. Hash the token, load row, reject expired/redeemed/revoked with the same 400 message. In one `db.batch`: insert `devices` (id `dev_…`, name from tenant code + sequence e.g. `CLOUDBOX-00017`, thumbprint = RFC 7638 JWK thumbprint of the public key; duplicate thumbprint → 409), insert `device_credentials` (opaque 32-byte token, hash stored, plaintext returned once), mark token redeemed. Audit `DEVICE_ENROLLED` actor `device`. Response per PLAN §7.
3. `requireDevice()` middleware: Bearer device token → hash → `device_credentials` join `devices` (status enrolled) → `c.var.device`. `POST /api/v1/agent/heartbeat` validates `AgentHealth`, stores `last_health_json`, `last_seen_at`, `agent_version`, returns `{serverTime, entitlementGeneration (from entitlements max generation or null), commands: []}`. `GET /api/v1/agent/entitlement` returns `entitlements.token` (compact JWE) and `generation` for the device's latest non-revoked row, else 404. WT-5 owns issuance and fills that column; you only read it. Audit nothing on heartbeat (not consequential) except transitions offline→online later. Add `POST /api/v1/agent/uninstalled` (Bearer device token): marks the device `revoked`, revokes its credentials, audits `DEVICE_UNINSTALLED` with actor `device`; idempotent; 204. WT-4 calls it during uninstall.
4. Staff device routes: `GET /api/v1/screens/fleet?tenant=&online=&q=` one loader: tenant, device name, online (last_seen < 2 min), last seen, agent version, windows build, key protection (mark `DEGRADED` when software), license state (from entitlements: none/active/expired by valid_until), enrolled at. Facets. ≤3 D1 round trips. `GET /api/v1/screens/fleet/:deviceId` detail with tabs data (overview, license, health json, audit). `POST /api/v1/devices/:id/revoke` gated `device.manage`, audited `DEVICE_REVOKED`, revokes credentials.
5. UI: Enrollment page (per-tenant token issue dialog showing the code once with copy button and expiry, table of tokens). Fleet page: operational table with the columns above, status pills (Online/Offline/Degraded key), filters (offline, degraded key, tenant), row → device detail with Overview / License / Health / Audit. Honest empty state: "No devices enrolled. Create an enrollment token under Enrollment and run CloudBox Server Setup on the machine."
6. Tests: token redeemed twice → second fails; expired fails; revoked fails; device appears under exactly one tenant; heartbeat with wrong token → 401; Tenant A admin cannot list Tenant B devices; fleet loader ≤3 D1 calls.

Demo path (curl is acceptable tonight, no Windows): create token in UI → `curl -X POST /api/v1/agent/enroll` with a generated RSA JWK → device row appears in Fleet as Offline → `curl /api/v1/agent/heartbeat` with the health document → Fleet shows Online, agent version → replay enroll with same token → 400 → screenshot.
