# WT-5 — Plans, subscriptions, entitlement issuance (Slices 3.1, 3.2 cloud side)
Model: **Opus 5.5** (crypto-sensitive: JOSE usage, key ids, generation monotonicity). Branch: `wt/p3-entitlement` from `phase-1/identity` (after foundation). Reserved migration: `0007` (should not be needed; `entitlements.token` is in the foundation).

Load: spec §9, §10, §32, §33; agent-notes `platform/cloudflare-workers.md` #20 (secrets), the "provider credentials" entry, `engineering/api-versioning.md`.

You own: `apps/worker-api/src/routes/v1/subscriptions.ts`, `entitlements.ts`, `apps/worker-api/src/entitlement/**`, `apps/worker-api/src/screens/subscriptions.ts`, `packages/licensing-contracts/**`, `apps/admin-web/src/routes/_app/subscriptions.tsx`, `_app/subscriptions.$id.tsx`, `apps/admin-web/src/api/subscriptions.ts`, `docs/runbooks/licensing-key-rotation.md`, ADR `docs/decisions/0004-entitlement-format.md`.

Deliver:
1. Plans are rows (seeded `cloudbox-6`). `GET /api/v1/plans`. Subscriptions: `POST /api/v1/tenants/:id/subscriptions` (plan, valid_from/until, overrides for max users/grace/warning days), `PATCH` status/dates, gated `subscription.manage`, audited `SUBSCRIPTION_CHANGED` with before/after. Tenant status derives from subscription at read time; do not duplicate state.
2. Entitlement format (`packages/licensing-contracts`): claims per spec §9.3 plus `iss:"cloudbox"`, `iat`, `jti`, `kid`. Build with `jose`: `new SignJWT(claims).setProtectedHeader({alg:'ES256', kid, typ:'cbx-entitlement+jwt'})` using the private key from secret `ENTITLEMENT_SIGNING_JWK` (P-256 JWK, generated once by `jose.generateKeyPair` in a documented one-off command, public half inserted into `signing_keys`). Then `new CompactEncrypt(jwsBytes).setProtectedHeader({alg:'RSA-OAEP-256', enc:'A256GCM', cty:'jwt', kid})` to the device's stored `device_public_key_jwk`. Explicitly reject unsupported `alg`/`kid` on the verify path. Unit-test: sign → encrypt → decrypt with a test RSA key → verify signature → claims equal; tamper one byte → fails; encrypt to key A, decrypt with key B → fails (this is the copy-protection primitive of Slice 3.4 at the format level).
3. Issuance: `POST /api/v1/devices/:id/entitlements/issue` gated `license.issue`, requires an active subscription on the device's tenant; `generation` = max+1 for the device (UNIQUE enforces it); store `claims_json`, `token`, `valid_until`. `POST …/revoke` gated `license.revoke`, sets `revoked_at`, audited. `POST …/renew` = issue with new dates (`license.renew`). Audit `LICENSE_ISSUED/RENEWED/REVOKED` with claims minus nothing secret (claims are not secret; the token is the confidential artefact — never log it).
4. Local verifier (TypeScript, in `packages/licensing-contracts`) `verifyEntitlement({token, devicePrivateKey, serverPublicJwks})` used by tests and later by the Windows side as the reference behaviour (document the equivalent .NET calls for WT-4: `Microsoft.IdentityModel.Tokens` JWE decrypt + ES256 verify).
5. Screen loader `GET /api/v1/screens/subscriptions` (tenant, plan, users, dates, status, days remaining, devices with current generation) and detail. UI: Subscriptions table with expiry pills (expired/expiring ≤30 d/active), detail with entitlement history per device (generation, issued, valid until, revoked), actions Issue / Renew / Revoke in confirmation dialogs (revoke needs a typed reason). Renewal-warning threshold visible.
6. Tests: issuance without active subscription → 409; generation strictly increases; revoke then `GET /api/v1/agent/entitlement` (WT-3's route) returns 404 — coordinate via handoff; permission boundary for each key.

Demo path: Tenants → Example Org → Subscription → create `cloudbox-6` valid 1 year → Fleet → the enrolled device → License tab → Issue → generation 1, token stored → `curl /api/v1/agent/entitlement` with the device token returns a compact JWE → decrypt with the test RSA private key in a script → claims show `device_id`, `max_managed_users: 6` → Revoke → 404 → screenshot.
