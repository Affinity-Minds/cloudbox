# WT-1 — Email OTP authentication + staff authorisation (Slices 1.1, 1.2)
Model: **Opus 5.5**. Branch: `wt/p1-auth` from `phase-1/identity` (after the foundation commit). Reserved migration: `0004` (only if Better Auth needs a table the foundation missed).

Load: agent-notes `platform/cloudflare-workers.md` §17 (Better Auth specifics) and the "origin check is gated on the cookie" entry, `engineering/roles-vs-capabilities.md`, `design/ux-patterns.md` "One-time codes". Use the installed `better-auth` skill (`~/.claude/skills/better-auth`) for the D1/Drizzle adapter wiring; it prevents the known adapter errors.

You own: `apps/worker-api/src/auth/**`, `apps/worker-api/src/authz/**` (fill the signatures WT-0 left), `apps/worker-api/src/routes/v1/auth.ts`, `apps/worker-api/src/email/**`, `apps/admin-web/src/routes/login.tsx`, `apps/admin-web/src/api/auth.ts`, `apps/admin-web/src/auth/**` (client, session hook, route guard in `_app.tsx` beforeLoad only).

Deliver:
1. `createAuth(env)` with Better Auth + `drizzleAdapter(drizzle(env.DB, {schema}), {provider:'sqlite'})` + `emailOTP` plugin (6 digits, 5 min expiry, single use, resend supersedes, rate limit per email/IP using Better Auth's rateLimit with D1 storage). `trustedOrigins` = production origin + `http://localhost:5173`. Host-only cookies (default). Mount at `/api/auth/*` **and** expose `/api/v1/auth/session` (current user + staff role + memberships) and `/api/v1/auth/logout`.
2. Email provider adapter `src/email/index.ts`: `sendOtpEmail(env, {to, code})` → `await env.EMAIL.send({ to, from: env.EMAIL_FROM, subject: 'Your CloudBox sign-in code', text, html })` using the Cloudflare Email Service `send_email` binding `EMAIL` (WT-0 adds it to `wrangler.jsonc`; types: `interface SendEmail { send(m): Promise<{messageId}> }`, errors carry `.code` such as `E_SENDER_NOT_VERIFIED`, `E_RATE_LIMIT_EXCEEDED`). Catch and record the outcome; never let a send failure change the HTTP response (anti-enumeration). When the binding is absent (unit tests, `wrangler dev` without remote bindings) and `OTP_DEV_ECHO=1`, log `console.log('[otp-dev-echo]', email, code)`; production never echoes (assert `ENVIRONMENT !== 'production'` at startup and in a test). Record the send result in `audit_log` as `AUTH_OTP_SENT` with `{messageId}` or `{errorCode}` (Better Auth returns 200 regardless). Plain, short email body: the six-digit code, expiry, and 'ignore if you did not request this'. No branding assets.
3. Anti-enumeration: identical response whether or not the email exists. Honeypot header enforced server-side (400, names nothing).
4. Bootstrap: on first successful verify, if `email == env.BOOTSTRAP_SUPER_ADMIN_EMAIL` and `staff_members` has no super_admin, insert the row and audit `STAFF_ROLE_GRANTED` with actor `system`.
5. `requireUser()` (session → `c.var.user`), `requireStaff()`, `requirePermission(key)` resolving `staff_members → role_permissions` **per request from D1** (one query, cached per request only). `requireTenantStanding(min)` resolving `tenant_memberships` for `:tenantId` in the path, never from a body field. 403 JSON `{error:'forbidden'}`; 401 `{error:'unauthenticated'}`.
6. Staff management API: `GET/POST/DELETE /api/v1/staff` (grant/revoke role) gated by `tenant.manage`-equivalent staff permission `staff.manage` (add key to the catalogue via request to WT-0 if missing — it is in the foundation seed as `staff.manage`). Audited `STAFF_ROLE_GRANTED/REVOKED`.
7. Login UI: email step → OTP step with `input-otp` six boxes, auto-submit on sixth digit, paste distributes, 30 s resend timer, `autocomplete="one-time-code"`, error and rate-limit states, no ornamentation. Route guard redirects unauthenticated users to `/login`. Logout in the sidebar user menu. Screenshot both steps.
8. Tests: verify flow with a stubbed mailer; expired, reused, invalid, rate-limited OTP; unauthenticated → 401; staff without permission → 403; super admin permissions are rows (delete a `role_permissions` row and prove the super admin is denied). Use `app.request()` with the D1 from `@cloudflare/vitest-pool-workers` once WT-6 lands it, else `better-sqlite3`-free approach: coordinate with WT-6 through your handoff, do not add your own harness.

Audit events: `AUTH_OTP_SENT`, `AUTH_LOGIN_SUCCEEDED`, `AUTH_LOGIN_FAILED` (no code, no enumeration), `AUTH_LOGOUT`, `STAFF_ROLE_GRANTED`, `STAFF_ROLE_REVOKED`.

Demo path: open `/login` → enter owner email → OTP arrives (or `wrangler tail` echo in dev) → paste → lands on overview with the user menu showing Super Admin → `/api/v1/staff` returns your row → logout → `/api/v1/auth/session` is 401.

Provided by WT-0 in the foundation and deploy workflow: binding `EMAIL`, vars `EMAIL_FROM`, `ENVIRONMENT`, `BOOTSTRAP_SUPER_ADMIN_EMAIL` (= soren@affinityminds.net), secret `BETTER_AUTH_SECRET`. If anything is missing, write it in your handoff and stub locally.
