# CloudBox Alpha 1 (v0.1) — scope, worktrees, ETA (written 2026-09-26 23:20 IST)

## Definition (owner, 2026-09-26)
Installable end to end: `CloudBox.Server.Setup.exe` on the lab PC → device enrolls → Super Admin logs in (email OTP) and issues a licence for N users → Agent detects and enforces it → private network up → N managed RDP users exist → RDP Wrapper/TermWrap runtime allows concurrent sessions → `CloudBox.Connect` on a second PC logs in with Tenant ID + Client ID + password and connects remotely.

Maps to spec Phases 0, 1, 2, 3 (+3.3 local verifier, 3.5 licence UI), 5 (5.1–5.5), 6 (6.1–6.7), plus the uninstaller (2.5). Explicitly **not** in v0.1: Phase 4 tamper hardening beyond the trusted-time seed, backups (9), OTA (10), maintenance/WOL (11), break-glass (12), tenant portal (13), alerts (14), drills (15), signing/notices (16). Phase 7 realtime is replaced by the 60 s heartbeat; Phase 8 commands limited to REFRESH_LICENSE.

## Provider support access (owner decision 2026-09-26: "super admin group always has access for maintenance and work")
- Network: the owner's **VPS hosts the NetBird control plane and is also the admin gateway**: an always-on peer in group `cbx-support` (plus staff machines enrolled by Super Admin only). Policy `cbx-support → cbx-server-*` on 3389 and the Agent management port is permanent; no request flow.
- Windows login: Server Setup creates a local administrator `cbx-support` per device with a random per-device credential, rotated on every use, stored encrypted in the cloud (AES-GCM via `crypto.subtle`, one master key as a Wrangler secret). Super Admin retrieves it with a fresh OTP step-up; retrieval is audited `SUPPORT_CREDENTIAL_RETRIEVED` and the Status app shows "Provider support access in use" while a session from a support peer is open. This gives standing access without approval friction while keeping every use visible and audited. Spec §21's request/approve/expire break-glass becomes the optional strict mode for tenants who demand it, not the default.
- This overrides spec §21.1 ("disabled by default") by owner authority (spec §0.1 item 1). Record as ADR 0008; WT-8 reviews the credential vault design before it ships.

## Risks specific to this alpha
- RDP Wrapper: TermWrap computes offsets automatically so Windows updates rarely break it, but Defender and other AV vendors periodically flag the binaries (upstream README says so). The adapter reports `repair_required` instead of failing silently; code-sign our Setup; keep the exclusion in place; still pause Windows updates on the lab PC during alpha.
- The VPS is the control plane: already-connected peers with direct WireGuard paths keep working if it is down, but new logins, new peers, and relayed (TURN) connections stop (spec §40/41 accept this for alpha). Mitigations in order: nightly backup of the management store, a second VPS with the documented HA setup after alpha, and the Worker monitoring the VPS as a fleet-level alert.
- Netmaker/NetBird/Headscale all need a coordination server we would host; that is the VPS and the single point of failure the owner rejected. Spec §4.8's Netmaker choice is superseded by owner decision on 2026-09-26 (ADR 0007).
- Credential brokering for RDP is the alpha's weakest security point; the design (Credential Manager, per-session cleanup, no command-line secrets) must pass WT-8 before any customer sees it.
